## 2. How it all connects

### 2.1 The app in one picture

```
                         KymMathsApp (@main)
                                |
                    NavigationSplitView, 8 rooms
   Today | School Maths | Patterned World | Labs Atlas | Polya Fluency
         | Maths Journal | Coach | Euclid's Workshop
                                |
                    every room reads and writes
                                v
        +------------------- AppStore -------------------+
        |  one @MainActor @Observable object, 894 lines  |
        |  holds: seed pack, selections, proof records,  |
        |  BKT skills, FSRS cards, journal, coach turns, |
        |  Euclid and Motif progress, settings           |
        +---+-----------+-----------+-----------+--------+
            |           |           |           |
            v           v           v           v
      SeedPackLoader  Learning   Database    PolicyDriven
      (JSON, once)    engines    Manager     AIProvider
            |        (pure)     (GRDB x3)        |
            |           |           |            +--> local canned reply (default)
            |           |           |            +--> Gemini / Anthropic / OpenAI
            v           v           v
       seed-pack.json  KymLearning  kb.sqlite, state.sqlite, mnemosyne.sqlite
                       (FSRS, BKT)  + UserDefaults (Euclid, Motif, settings)
                                    + Keychain (API keys)
                                    + App Group snapshot file
```

In plain words. The app has one brain, `AppStore`. Every screen asks it for data and tells it what the learner did. `AppStore` loads the content once from a JSON file, runs the marking and scheduling rules, and saves to three SQLite databases. The coach goes through one routing object that picks either a canned local reply or a real model.

### 2.2 Where the content comes from

```
source/export_kymmaths_pack.py   (2,591 lines, all content is Python literals)
        |
        +--> Resources/ContentPacks/kymmaths-seed-pack.json   (394 KB)
        |          |
        |          +--> SeedPackLoader (Codable, every field required)
        |          |        decode error -> empty pack -> crash on [0]
        |          +--> DatabaseManager seeds tables ONLY when they are empty
        |
        +--> Resources/PatternedWorldBook/index.html           (126 KB)
                   |   21 canvas sandboxes + the pack inlined again
                   +--> <iframe> atlas/examples/<route>/index.html#N
                              vendored copy of @saxster/atlas (268 files)
                              three.js from cdn.jsdelivr.net, fonts from Google
```

In plain words. One Python script is the only author. It writes the JSON the Swift app reads and the web page the book room shows. The web page embeds a copy of the Atlas figure library. Atlas pages fetch three.js from the internet, so 3D figures need a network.

### 2.3 What happens when she answers a school question

```
 typed answer
     |
     v
 QuestionProofService.evaluate            (LearningEngines.swift:200-221)
     |   pass if  answer CONTAINS >= 50% of the keywords
     |         or answer == fadedAnswer
     |         or polynomial-equivalent
     v
 proof level: unseen -> assisted -> shaky -> proven -> secure
     |   "assisted" comes from a flag held by the VIEW, not the store
     |   pass days counted with the local calendar day
     +--> BKT update per topic (runs on every Submit)
     +--> FSRS card scheduled
     +--> state.sqlite (try?, errors dropped)
     +--> refreshState(): reload all 12 tables, rewrite widget snapshot
```

In plain words. Marking is a substring search. Mastery, review dates and the "proven" badge all trust that search.

### 2.4 What happens when she messages the coach

```
 text -> SafetyEscalationService.scan  --concern--> helpline text + parent alert, stop
     |
     v

     |
     v
 PromptSegmentComposer -> PolicyDrivenAIProvider
     |        default policy .localPreferred
     |        local provider never throws, so no model is ever called
     v
 DevelopmentalResponseValidator -> transcript (memory only, lost on quit)
```

The voice panel has the same scan but no parent alert, and no audio. The scratchpad "image analysis" is canned text.


This is the best-built part of the app. Goals measure geometry, so a tool cannot fake a construction. Every Euclid and motif answer was recomputed and is correct [reviewer].

## 3. Where it breaks today, ranked

1. **Fixed on 2026-11-15, see section 11.** **Marking accepts wrong answers and rejects right ones.** [checked: code; reviewer: simulation] `LearningEngines.swift:206` uses `contains`. 48 of 64 questions have one keyword. Question ch07 focus has keyword `x`, so "x = 7" passes and the right answer "3" fails. Two reviewers independently found 15 wrong answers accepted and 12 right answers rejected. Everything downstream (mastery, review dates, badges) inherits this. LD-1, CT-1.
2. **Screens record learning that did not happen.** [checked: UI-1, UI-3] "Reveal All & Log Recall Score" logs full marks whatever was typed (`LabsAtlasHomeView.swift:286`). Speed check passes "1" for 10, 12, 15, 16 and 1596 (`PolyaFluencyHomeView.swift:453`). [reviewer] Empty text unlocks gates (UI-2). Re-submitting farms mastery 0.42 to 0.99 (LD-3). "Reset for Unassisted Proof" clears the assisted flag after the solution was shown (UI-5). Motif "Show the answer" precedes the board answer (GEO-2).
3. **Features are presented as live but are stubs.** [reviewer, AI-1 and AI-3 checked] The coach never calls a model by default. Live Voice has no audio and no socket but shows "Live · Gemini". "4-Expert Council", "KORA Safety Eval 16/16", "Wolfram-Verified", scratchpad vision, scanner, calendar and PencilKit ink are all canned or missing.
4. **Voice panel safety path does not alert the parent.** [checked] `LiveMentorVoiceEngine.swift:438-449` shows the helpline but never calls `escalate`. Region is hard-coded to India.
5. **A generated question can ask for a negative number of people.** [checked] `QuantitativeMathsEngine.swift:227-233`. Seed 3 gives an overlap of -5. 34 of the first 60 seeds give zero or less.
6. **A wrong-answer trap equals the right answer.** [checked] Determinant template with a=4, d=2 gives det 6 and trace 6, so a correct answer could be told it fell for the trace trap.
7. **The book room throws on every term highlight.** [checked: source] The highlight block uses `RED`, `BLUE`, `AMBER`, `GREEN`, `W`, `H`, none of which exist. After the throw the canvas transform stack is left unbalanced. The health probe cannot see it. CT-3, UI-10.
8. **The app runs from source only because of a hard-coded home-directory path.** [checked] `SeedPackModels.swift:427` and `PatternedWorldWebStageView.swift:69-84`. Under SwiftPM resources sit in `Bundle.module`, which the code never asks.
9. **Launch crash paths.** [checked: code] A decode error returns an empty pack, then `AppStore` indexes `[0]`. `DatabaseManager` uses `try!` on open, migrate and seed. LD-11, LD-12.
10. **Content updates never reach an existing install.** [reviewer] Seeding runs only when tables are empty. LD-13.
11. **Teaching text is wrong in places.** [checked: CT-2] The determinant tip and the generated-question hint both say box minus four triangles leaves ad - bc. It leaves ad + bc; two b×c rectangles must go too. [reviewer] Bayes copy says the test "is right only 28% of the time" (CT-4). Motif M3 names the wrong condition for the dart (GEO-6). Vectors chapter routes to a linear-graphs figure (CT-7).
12. **Offline claim is false.** [reviewer] 38 of 43 Atlas pages load three.js from a CDN. CT-6, UI-12.

## 8. Refactoring map

Ordered so each step makes the next one smaller.

1. **One answer-checking module.** Today there are five checkers: school questions, speed cards, prerequisite brackets, generated questions, faded steps. Build one on `STEMRational` and `STEMPolynomial` that takes accepted forms and returns right, wrong or cannot-tell. Fixes D1 and removes four bugs.
2. **One evidence loop.** Proof level decides. BKT updates once per attempt. FSRS only schedules. "Assisted" lives in the store. Fixes D2.
3. **Split `AppStore` (894 lines)** into content, learning, coach and geometry stores behind the same observable facade. Move UserDefaults keys into one enum. Remove duplicated defaults between `init` and reset.
4. **Split the god files.** `LearningEngines.swift` (1,594 lines, six engines). `AdvancedAIPedagogyEngines.swift` (1,466 lines, eleven sections). `LiveMentorVoiceEngine.swift` and `TutorCanvasView.swift` mix model, client, controller and view. `JournalBridges.swift` holds seven unrelated components. `EuclidWorkshopSession.swift` (856 lines) and `MotifPageView.swift` (648 lines).
5. **Typed fields.** Roles ("learner", "mentor", "safety"), tiers, colour roles and topic codes are strings. Make them enums.
6. **Persistence.** All learning state in `state.sqlite`. Idempotent upsert seeding keyed by pack version. Replace `try!` and `try?` with one error path the UI can show. Move reads off the main thread. One generic JSON-defaults store for Euclid and Motif until they move.
7. **Exporter.** Content as one data file per chapter with section tags and accepted answers. A JSON Schema shared with Swift. A validator that recomputes answers and runs right and wrong answers through the marker. Sandbox JS in its own file with node tests. A vendor script that pins the Atlas commit, prunes unreached files and vendors three.js.
8. **Shared code.** `Design/` duplicates files in four sibling apps; the coach duplicates `teaching_kit` validators. Move to the kit after the dead code is gone.
9. **Tests.** `KymMathsTests.swift` is one 965-line suite. Split by engine. Add the missing seams: routing, `sendMentorMessage`, tangency, layer switch mid-attempt, old-shape progress JSON, tools on short inputs.

## 11. Decision D1 landed: school-question marking

Nothing is committed. These changes sit in the working tree on `main` with the section 10 changes.

### What a question now carries

Each of the 64 school questions has an answer key in place of its keyword list.

```
answerKey
  parts     every part must be found for the answer to be right
    label   what the learner sees when the part is missing ("LCM", "the x-intercept")
    anyOf   the part is found when any one matcher passes
  accepts   sample right answers
  rejects   sample wrong answers
```

| Matcher | Passes when | Used for |
|---|---|---|
| number | a number standing on its own equals the value. `tolerance` and `simplest` are optional | 24, -16, 5/14, 0.00409 |
| sequence | these numbers appear in order with nothing between them | points, vectors, ratios |
| form | this exact expression appears, spacing ignored. Every accepted form is listed | 5x + 3, x ≤ 4, 6ab(3a − 2b) |
| words | every group has a whole-word hit and no forbidden word appears | the three worded questions |
| all | every listed matcher passes | "4" together with "decrease" |

A number counts as standing on its own when it is not a coefficient (3x, 4(…), 2√2), not a base or an exponent (10², x^2) and not a subscript (S₂₀). So "x = 7" no longer passes a question whose key was the letter x, and "3" on its own is right for "x = 3".

### Where it lives

- `KymMaths/KymMaths/Core/Learning/AnswerKey.swift` (new): the key, the matchers and the reader for typed answers.
- `source/export_kymmaths_pack.py`: `ANSWER_KEYS`, one entry per question id. The exporter stops if a question has no key or a key has no question.
- `QuestionProofService.evaluateAndRecord`: right means every part found. The 50% keyword rule, the `fadedAnswer` equality shortcut and the polynomial shortcut are gone.
- `SchoolMathsQuestion.markSchemeKeywords` is deleted. Hints, the scratchpad coach note and the feedback screen now use part labels.
